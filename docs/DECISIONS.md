# Design decisions and why (from the planning chat, 2026-11-15)

Source material for the post's methods section and a possible "how this was built" sidebar.
Milestone-level results live in JOURNAL.md; this file holds the reasoning behind the design.

## Framing
- **Agent-config census before skill census.** Plain counting of both is already published (Zarzycki: 22,854 repos; Galster et al.: 4,738). The value here is new angles (wrongness, token cost, change over time) plus a tool readers can use. Skill *verification* is a separate, later post.
- **Standalone post, not "part 1 of a paper".** It has to be useful on its own: a benchmark, a finding, a trend, a tool (`neri check`) and a dataset.
- **The headline is "how much is already wrong".** It's measurable without an LLM, it's something every reader can act on, and an earlier 25-file probe suggested about 27% dead paths. That probe is too small to be a finding; the post's number comes from M5-validated checks.

## Scope
- **CLAUDE.md + AGENTS.md only.** Cursor rules, copilot instructions and others are recorded only as presence flags (A7). This keeps the scope shippable in a week.
- **Skills are excluded,** apart from free presence flags taken from the tree we fetch anyway.
- **Progressive disclosure is measured:** `@imports` are always loaded and nested files are loaded on demand. "Always-loaded token cost" counts the root file plus its imports, not the root file alone.

## Sampling
- **Stars >= 10, pushed within 180 days, not a fork or archived.** This removes toy and template noise. The trade-off is a skew toward established projects, which the post states as a limitation.
- **~10K repos, not 50K.** That gives about ±1% precision on descriptive percentages, so more adds nothing for this post.
- **Explore/confirm split by hashing the repo name.** The post uses only the explore half; the confirm half is reserved for a future preregistered paper.
- **Bucket sampling instead of full enumeration.** Listing all ~2.2M files at code search's ~9 req/min takes 40+ hours. Instead, the size buckets are shuffled once with a fixed seed and taken from the top until 100K candidates; going to 300K later continues down the same order. Every file has an equal, recorded inclusion probability.
- **Kept fine-grained buckets despite the ~9h ETA.** Splitting only the selected coarse buckets would be faster, but it would sample from far fewer, wider size ranges and make file-length estimates noisier. Length and token cost are headline numbers, so we accepted the extra time.

## Time and models
- **Change over time is included (A8) on ~1.5K repos.** It's the angle that makes the post more than a snapshot. Every model and tool release date needs an official source URL.
- **Descriptive only.** Model releases coincide with Claude Code changes, `/init` template changes and the arrival of AGENTS.md. We report co-occurrence and check confounds (share of boilerplate per era, repo age), but make no causal claims.

## LLM use and token budget
- **Deterministic pipeline.** An LLM is used only to validate topic labels (300 sections, Haiku via the Batch API, $30 cap), and to label all sections only if rule agreement is under 85%.
- **Claude Code never reads raw data.** It sees only summaries of 50 lines or fewer. Long jobs run as background processes (costing no tokens) and the session ends its turn instead of polling. STATUS.md, JOURNAL.md and the commits let any new session resume.

## Ethics and licenses
- **Pointers plus derived features only.** We never redistribute file text, since many repos are unlicensed. Quotes are under 2 lines and only from permissively licensed repos.
- **Wrong-file examples are anonymized.** The point is the pattern, not shaming anyone.
- **Official API only, at polite rates, no HTML scraping.**

## Tooling
- `neri` is taken on PyPI, so the package is published as `neri-check` and the CLI is still `neri`.
- The Anthropic key lives only in `neri/.env`. A globally exported key conflicts with Claude Code's subscription login.

## Scope addition: commands census, skills extraction, local explorer (2026-11-15, human request)
- **Commands census (extends A2).** Rank the commands in agent files after normalization (`npm run test` -> `npm:test`, `uv run pytest` -> `uv:pytest`, `pytest -x` -> `pytest`), overall and by detected toolchain (from root lockfiles/manifests). Unknown tools are not counted, so prose never enters the census; negated lines ("never run X") are excluded. Counted per repo (a repo mentioning a command twice counts once; mentions are reported separately).
- **Skills extraction (A7 deepening, still explore-only).** For explore repos with `.claude/skills/*/SKILL.md`, fetch SKILL.md from raw at the pinned sha (symlinked skill dirs are resolved through the link) and run the same extraction. Extra features: tokens, frontmatter, allowed-tools, commands, script references in text, files and scripts in the skill dir. This only reads skill *text* for command/tool extraction; skills content analysis and execution remain out of scope for post 1.
- **Local explorer.** `reports/explorer.html` is for the human only: it embeds third-party path strings, is gitignored (`reports/*.html`), and is never published. Its tiers are the post-hoc, unvalidated M5 tiers and are labelled as such. The M5 decision (options a/b/c) is untouched by this work.
- Why now: cheap (no LLM, uses already-cached trees), descriptive, and useful for the post even if the wrongness claims are dropped (option b).

## Rigor rules (2026-11-15, human request)
- **DEV / report split.** The explore-half repos of checkpoint c5000 (2,508 repos, frozen in `data/sample/dev_ids.parquet`, hash in `dev_ids.sha256`) are the DEV set. They were used to tune the detectors, write fixtures and run M5 rounds 1-3. **Every reported number excludes them: report on c50000 minus c5000** (checkpoints are nested prefixes, c5000 is inside c25000 and c50000). `neri features --summary` runs in report mode by default; `--include-dev` is for tuning only. `reports/numbers.json` (M8) must be built from non-dev repos only. The explorer marks dev repos and leaves them out of its distributions.
- **M5 re-validation protocol.** (1) The detector and the `moved` tier definition (`moved-v2`: letter-case match, same directory with another extension, or a unique non-generic basename elsewhere) are frozen by a commit *before* the sheet is drawn. `neri validate` refuses to draw a sheet if `src/` or `tests/` has uncommitted changes, records the git head and the sha256 of `core.py` and `census.py`, and `--score` warns if the detector changed afterwards. (2) The sheet is fresh: non-dev repos only, 50 paths + 25 commands where available, at most 2 rows per repo. (3) Two independent labelers use the same written rubric (`reports/validation_rubric.md`): Claude Code, and a subagent that gets only the rubric and the sheet, never the detector code. We report raw agreement, Cohen's kappa, and precision under each labeler and under "both say TP". Ambiguous rows count as FP. (4) The human spot-checks 10 rows. (5) The tier numbers measured on dev rows (10/10 for `moved-v2`) are post-hoc, tuned on those rows, and are not evidence. Gate unchanged: precision >= 90% with the Wilson interval reported; commands are scored separately.
- **Truncated trees are never evidence of absence.** If GitHub truncates the recursive tree, refs the partial listing calls dead are re-checked with per-directory non-recursive walks; found = alive, otherwise `unknown` (excluded from all wrongness numbers and counted in the report). This fix was committed before the fresh sheet (round 4) is drawn.
- **Human spot check result (r3, 10 rows): agreement 7/10, kappa 0.40**, three detector errors found (two truncated-tree, one `cd` scoping) and fixed before the fresh sheet is drawn; the rubric was extended with the human's reasoning (user-project paths, conditionals, `cd`, wildcard families, truncated listings). The detector frozen for round 4 is whatever commit is HEAD when `neri validate` draws the sheet; it is recorded in `reports/validation_freeze_r4.json`.
- **Reference categories (2026-11-15, from the human spot check).** A reference is ALIVE, or one of: **STALE** (expected in this repo now and missing; includes moved/renamed and case mismatch; the ONLY category that counts toward the wrongness headline), **EXPECTED_CREATED** (per-user/setup files, build/runtime outputs, "copy X to Y" targets, ignored paths), **NOT_A_REFERENCE** (examples, placeholders, wildcards/patterns, conditionals, negated or historical mentions, other projects, the user's project), **UNKNOWN** (truncated tree, symlink/submodule ancestor, `cd` into an unindexed folder, ambiguous manifests). Each category is reported separately. Commands honour `cd` and are checked against the manifests of the directory they run in.
- **Validation protocol v2.** Fresh sheet from non-dev repos with the detector frozen by a commit; every row shows source line, +-3 lines of context, a non-English flag, the checker's evidence and the parent folder, but NOT the checker's verdict; ~20 blind exclusion-audit rows (from EXPECTED_CREATED/NOT_A_REFERENCE) are mixed in to measure how many real stale refs the exclusion rules hide. Two independent labelers (Claude Code, and a subagent that has seen neither the detector code nor any earlier label), then a 10-row human check. Reported with CIs: 5-way and binary kappa, precision under each labeler and for both-STALE, and the hidden-stale rate. The headline is publishable only if precision (Wilson lower bound) clears the gate AND the audit shows the exclusions hide little.
- Why: the detectors were tuned on the same rows they were scored on in rounds 1-3 (precision 16% -> 34% -> 56%), so those numbers describe tuning progress, not accuracy on unseen repos.

## Reproducibility
- **Reproducible from the frozen pointers on.** `neri freeze-pointers` writes `data/public/candidates-frozen.parquet` (owner, repo, path, blob sha, size bucket, bucket id, inclusion probability, split), `buckets-frozen.parquet` (every size bucket, its count, its position in the seeded shuffle, whether it was paged), `repo-meta-snapshot.parquet` (stars, fork/archived flags, pushed/created dates, license, pinned head sha at the snapshot) and `FROZEN.json` (snapshot date, seed, thresholds, counts, sha256 of each file, code git head, library versions). From these: the explore/confirm split (sha256(owner/repo) % 2), file fetches at pinned shas (the blob sha verifies content), every feature, the seeded sampling and bootstrap, and the figures are deterministic. No third-party file text is in the frozen files.
- **Not reproducible.** (a) The code-search enumeration: GitHub's index changes, results have no stable order, queries are rate-limited to 10/min, and totals are lower than the design's estimates because code search de-duplicates; a rerun would produce a different pointer list, which is why the list is frozen and published. (b) Repo metadata at snapshot time (stars and push dates move), hence the snapshot file. (c) Repos deleted, renamed, made private or force-pushed since the snapshot. (d) LLM batch labels (M6) if used: model outputs are not deterministic, so the labels themselves are published.
- The freeze must be run once enumeration is complete (`enumeration_complete` in FROZEN.json says whether it was); it refuses to overwrite without `--force`.

## Second population stratum: the long tail (2026-11-15, human request)
- **Why.** The post has to describe all developers who write agent files, not only popular repositories. The M2 funnel on c25000 shows why this matters: of 11,698 explore candidate repos, 10,717 (91.6%) have fewer than 10 stars, so the original `stars >= 10` filter describes about 1 repo in 12 (842 established vs 7,950 long-tail repos before the dev exclusion). Whether established and long-tail repos write different files (size, structure, style, ecosystem, wrongness) is itself a finding, so every headline number is reported for **established**, **long tail** and **weighted overall**, plus the long-tail-minus-established difference with a bootstrap CI.
- **Strata.** *Established* = stars >= 10, not fork, not archived, pushed within 180 days, size 200 B-100 KB; the existing star x type stratified sample, unchanged. *Long tail* = stars 0-9 with the same other filters; a seeded simple random sample of `longtail_target` (2,500) repos drawn from the NON-DEV explore candidates of c50000 (`data/sample/c50000/longtail.parquet`). Forks are already dropped at enumeration and the size bound holds by construction of the search buckets (the funnel shows 0 for both); the real size/root-file check happens at fetch.
- **Weights.** Every repo carries `N_h` and `sample_prob` (long tail: n / N_h; established: per star x type stratum) and the report weights by 1 / (P(bucket sampled) x sample_prob), so the overall estimate restores the population proportions (the tail is ~9x the established population and sampled at a lower rate). The stratum sizes are stored in `data/sample/c50000/strata.json` (N_h, n, sampling fraction, star distribution of the tail, non-dev established N_h). Estimates are domain estimates: repos that turn out to have no root CLAUDE.md in range at fetch time drop out without renormalising, as for the established stratum.
- **Order of work.** The long tail is fetched and featurised only after the c50000 checkpoint pipeline has finished (`neri longtail`, waits for the pipeline marker). The M5 validation sheet r4 is drawn from the established stratum; the detector's precision must also be checked on the long tail (a second sheet) because hobby repos may write differently.
- **Caveat.** The dev set (c5000) stays excluded from every reported number in both strata.

## Weights, populations and nested-only repos (2026-11-15, human request)
- **N_h is non-dev in both strata.** Established star x type populations are counted over NON-DEV explore repos that pass the filters (c50000: 933 / 338 / 104 = 1,375); the long tail likewise (13,773). The established sample was drawn before the dev split, so its sampling probability is post-stratified to the non-dev population: `sample_prob = n_nondev_sampled / N_nondev` per star x type stratum (`strata.apply_nondev_probs`, applied whenever `strata.load_explore` runs). `tests/test_weights.py` asserts that the sum of `1/sample_prob` over the non-dev rows equals the non-dev population of each stratum, and that the two strata's weights add up to their own populations, so the weighted overall estimate does not over-represent the established stratum (the tail is ~91% of the population). `neri strata` writes `strata.json`; `neri report` refuses to run without it.
- **Inclusion probability counts every agent file.** A repo enters the candidate pool through any of its CLAUDE.md files, each in its own size bucket, so `P(repo in pool) = 1 - prod (1 - p_name)^(number of DISTINCT size buckets its files of that name fall in)` (root and nested; two files in one bucket are one chance). The earlier version used only the root file, which under-weighted monorepos with many nested files and gave nested-only repos probability 0. Files beyond the fetch cap of 40 nested files (sizes unknown) are assumed to fall in distinct buckets, an upper bound on k. Repos with probability 0 (no in-range file) cannot be weighted and are excluded with a printed warning. Final weights are `1 / (P(in pool) x sample_prob)`; because they vary (max/min 89 on c50000) the report prints the Kish effective n per scope and keeps unweighted values next to weighted ones.
- **Nested-only repos are a structure type, not a drop.** A repo with no usable root agent file but an in-range nested one is `structure = "nested-only"`. Primary file rule: the SHALLOWEST in-range nested file named CLAUDE.md (the name the stratum was sampled through; any agent file if there is none), ties broken by the LARGEST size, then by path. Nested files are capped at 40 per repo keeping the shallowest. Nested-only repos are included in A1 shape/tokens, A3, A5, A7 and the commands census, with the primary file as the file of record. They are NOT in A2 (paths in a nested file may be relative to its own folder) or A4 (needs both root files). Their always-loaded cost is 0 by definition (the root loads nothing), so always-loaded statistics are measured over repos WITH a root file. The share is reported per stratum (`a1.structure.nested_only`: 10% established, 7% long tail on c50000). The 20.2% in the M2 funnel counted repos whose sampled candidate files were all nested; many of them have a root file in a size bucket that was not sampled, so the true nested-only share is about half that.

## Limitations: what code search can and cannot see (sources read 2026-11-15)
- **Archived repositories are not in the population**: "Archived repositories are not searchable" (https://docs.github.com/en/search-github/searching-on-github/searching-code). Observed: 0 archived repos among 11,698 c25000 explore candidates.
- **Forks are almost entirely absent**: code in forks "is only searchable if the fork has more stars than the parent repository" and has at least one commit pushed after creation (same page); enumeration additionally drops every result flagged as a fork. Observed: 0 forks among the candidates.
- **Other stated limits** (same page and https://docs.github.com/en/rest/search/search): only the default branch is indexed; only files smaller than 384 KB; only repositories with fewer than 500,000 files; only repositories with activity (or that appeared in search results) in the last year are searchable; at most 1,000 results per query and 10 requests per minute for the code search endpoint. The population is therefore "public, active, non-archived, non-fork repositories whose default-branch CLAUDE.md (<384 KB) code search indexes", not all of GitHub.
- Code search also de-duplicates, so enumerated totals are lower than the design's 1.09M / 1.13M estimates (c50000 pool: 876,678 CLAUDE.md files listed).

## Methods box: definitions (source text for the draft; state once)
- **Weighted "overall"** = the candidate population covered by the sampled buckets (repos that code search returned through the randomly selected size buckets of CLAUDE.md and AGENTS.md files), scaled to GitHub-wide via inclusion probabilities: each repo is weighted by 1 / (P(it entered the candidate pool) x P(it was drawn within its stratum)). "GitHub-wide" means public, active, non-archived repositories that code search indexes (see limitations). The same sentence is in `numbers.json` (`definitions.overall`).
- **Sensitivity (weights trimmed at the 99th percentile).** Every cell carries `sensitivity.trimmed_value`, `delta` and `sensitive` (|delta| > CI half-width). Result on the interim c50000 snapshot: trimming changed 0 of 400 cells (max |delta| 0), because the weights are nearly two-valued (long-tail single-file repos all weigh 1 / (p_pool x p_sample) = 89.3 and no weight exceeds the 99th percentile). So the p99 trim is a null check, not evidence of robustness to heavy tails; the unweighted value is reported next to every weighted one as the other bound, and the Kish effective n is in `meta.weights`.
- **Cells and CIs.** Bootstrap 1,000 resamples, repo-level (the repo is the cluster, one row per repo and file type), vectorised; every cell has n and a `low_n` flag when n < 100; token shares are ratio estimators (sum of weighted numerators / sum of weighted denominators).

## New features: definitions (POST1-PLAN section 3)
- **Directory-tree dump:** a fenced code block with box-drawing tree characters (├ └ │) on 2+ lines, or 8+ consecutive path-like lines (a path or file name with a known extension, optionally followed by a comment); spans are merged. Reported as share of files and token share (tokens in dumps / all tokens).
- **Overview-type section:** a section whose heading matches `overview|introduction|about|project structure|architecture|tech stack` (to the next heading of the same or higher level; nested matches merged). Share of files and token share. This is a pattern match on headings, not a judgement that the section restates the README.
- **Stack:** the distinct files among CLAUDE.md, AGENTS.md (any depth), `.cursor/rules/` or `.cursorrules`, `.github/copilot-instructions.md`, GEMINI.md (any depth), `.windsurfrules`; reported as the size distribution. **Bridge:** CLAUDE.md is a symlink to AGENTS.md, or is only/mostly an `@AGENTS.md` import (everything else in the file, headings excluded, <= 200 characters). The reverse (AGENTS.md symlinked to CLAUDE.md) is reported separately.
- **Skills depth:** SKILL.md files per repo among repos with fetched skills (median, p90), and the share of skills whose folder has a `scripts/` directory (ratio estimator, clustered by repo).

## Limitations added (2026-11-15)
- **Tokenizer is a proxy:** tiktoken `o200k_base`, not Anthropic's tokenizer. The planned calibration on 50 files against Anthropic's token-count endpoint has NOT been done yet (needs the human's go-ahead; it sends 50 public files to the API); until then token counts are labelled "proxy" everywhere.
- **Snapshot date 2026-11-15:** all files are read at pinned commit shas recorded at that date; repos pushed, renamed or deleted later are not reflected. Search results and star counts are as of that date.
- **Stars are a popularity proxy,** not quality or usage; the established/long-tail split at 10 stars is a convenience boundary, and 71% of the long tail has zero stars.
- **Bridge files are under-counted:** a CLAUDE.md that only says `@AGENTS.md` is a few bytes, below the 200 B size floor, so it never enters the pool through its own bucket; import-style bridges are a lower bound. Symlink bridges remain visible through the AGENTS.md side.
- **Truncated trees** (about 0.2% of repos) can undercount ecosystem/stack presence; `tree_truncated` is stored per repo.

## 2026-11-16 Extras for post 1 (deterministic; all in numbers.json; aggregate only, never name repos)
- **README overlap:** root README* fetched at the pinned sha via raw (≤300 KB; none/unreadable = no README). 5-word shingles over lowercase `\w+` words of the whole agent file vs the README. A *line* overlaps when ≥50% of its shingles occur in the README; overlap tokens = o200k tokens of those lines. Denominator: files in repos with a readable README and ≥1 shingle.
- **Drift:** repos with root CLAUDE.md and AGENTS.md, excluding bridges (symlink either way, or CLAUDE.md that is only/mostly an `@AGENTS.md` import). Line-Jaccard over normalized non-empty lines (markdown punctuation stripped, case folded). "Diverged" = Jaccard < 0.5. "Different test/build commands" = both files name ≥1 test/build command (normalized cmd matches test|tests|pytest|jest|vitest|mocha|cypress|ctest|rspec|phpunit|check or build|run|dev|start|serve|compile|package|make) and the two sets are not equal.
- **Package-manager mismatch (pm_check):** a file names npm/yarn/pnpm/bun (or pip/uv/poetry/pipenv/conda) in a command while the repo has exactly one lockfile of that ecosystem that points at a different manager. HELD: numbers stay out of numbers.json and the draft until the human approves reports/pm_check.md.
- **Scorecard (6 checks):** names a test command; names a build/run command; has ≥1 explicit "don't" (regex never|don't|do not|must not|should not|shouldn't|avoid|forbidden, outside code fences); no tree dump; no overview-type section; always-loaded tokens below the weighted population median of that file type (nested-only repos excluded from the score).
- **D1 settings:** committed `.claude/settings.json` and `.claude/settings.local.json` fetched at the pinned sha. Broad Bash = allow contains `Bash`, `Bash(*)`, `Bash(*:*)` or `Bash(**)`. Network = allow starts with WebFetch/WebSearch or Bash(curl|wget|ssh|nc|scp …). Bypass = `permissions.defaultMode == bypassPermissions`. Hook purpose by regex on the hook command (format/lint, test, guard, notify, other; one hook can have several). Denominator: repos whose committed settings parsed. A committed file can differ from what a developer runs locally.
- **D2 source bytes:** sum of git-tree blob sizes of files with source extensions (py js jsx ts tsx mjs cjs go rs java kt swift c/cpp/h cs rb php scala sh lua r jl dart ex erl hs ml clj vue svelte sql html css scss m zig nim pl), excluding paths under node_modules, vendor, third_party, dist, build, target, .git, __pycache__, site-packages, venv, bower_components, Pods, generated, gen, .next, coverage, docs, doc, and minified/generated/lock/.d.ts names. Docs, data, images, binaries and lockfiles are not counted. Truncated trees are excluded. **Lines of code were not counted** (that needs fetching every source file), so "tokens per 1K source lines" is replaced by "tokens per 100 KB of source". Agent bytes = characters of the file of record.
- **D3 age:** `createdAt` from GitHub GraphQL at enumeration vs snapshot date; bands <6 months, 6–12 months, 1–2 years, 2+ years. No tool launch date is claimed. Note: the population was drawn from repos pushed in the last 180 days, so old repos are those still active.
- **D4 language:** lingua (offline, all languages, minimum relative distance 0.2) on prose with code fences, inline code, URLs and markup removed; first 1,500 characters; <40 letters = undetected. Short or mixed technical text is error-prone, so shares are of detected files and are approximate. Unweighted Tamil count reported in numbers.json (`d4.tamil_files_unweighted`).
- **D5 tone:** persona = a non-code line starting "you are / you're / act as / your role is / as a(n) expert|senior|experienced"; please / thank you|thanks word match; vendor-or-model naming = claude (code) / opus / sonnet / haiku / anthropic / gpt-N / chatgpt / codex / gemini / copilot / cursor / windsurf / cline / aider / openai, after removing file names (CLAUDE.md, AGENTS.md, GEMINI.md, .claude, .cursor, .github/copilot…). Tool-neutral = names none.
- **D6 security keywords:** secure|security, secret(s), credential(s), password(s), api key, auth / authentication / authorization / authorize / authenticate, oauth, vulnerabilit(y|ies), encrypt*, sanitiz*, sql injection, xss, csrf, private key (outside code fences). Agent READMEs' 14.8% (security, v2) is a different corpus, labeler and definition; compare as context only.
- **X1 placement:** non-empty lines outside fences split into thirds by index; emphasized = SHOUT words (IMPORTANT|CRITICAL|MUST|NEVER|ALWAYS|MANDATORY|REQUIRED|FORBIDDEN) or an all-caps line of ≥3 words; negated = the scorecard "don't" regex. Files with ≥6 non-empty lines; ratio estimator of counts by third. "Long" = more non-empty lines than the weighted median. A uniform spread would be ~33% per third. "Lost in the Middle" (Liu et al.) is in claims_to_verify.md and NOT cited until verified.
- **X2 smells:** vague phrases (clean code, best practice(s), be careful, high quality, as needed, as/when/where/if appropriate, good practices, industry standard(s), production-ready, maintainable/readable code, write good code); duplicate = identical normalized list item (≥4 words) twice; contradiction = "always|must (use|run|prefer|include|keep|follow|write) X" and "never|do not|don't|must not|should not (same verbs) X" with the same first two words of X; template leftovers = TODO, FIXME, TBD, XXX, `<your …>`, `[your …]`, `[insert …]`, `{{…}}`, lorem ipsum, `[project name]`, `[describe …]`. Pattern matches, not judgments; reports/smell_check.md holds 20 flagged rows for review before reporting.
- **X3 deontic:** list items classified in order prohibition > obligation > permission > description by modal regex (see xfeat.py). A pattern match, not an interpretation.
- **Deferred to post 2:** viral instructions / origins, reading level vs README, dollar-cost framing.

## Round 3 definitions (2026-11-16)
- **Popular stratum is now a census.** Every eligible non-dev stars>=10 repo in the candidate pool was fetched (3,761); `explore.parquet` was extended (original kept in `data/sample/explore_original.parquet`); post-stratified sample_prob = 1. Weights now differ only through search inclusion probabilities.
- **Generator signature (`sig_init`):** a line matching /provides guidance to claude code/i in the first 10 non-empty lines of the primary file.
